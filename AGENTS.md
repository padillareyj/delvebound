# AGENTS.md: Guidance for AI agents working on Delvebound

Read this before changing anything. [DESIGN.md](DESIGN.md) is the source of truth for rules, formulas,
and schema. If code and DESIGN.md disagree, stop and flag it; don't silently "fix" one to match the other.

## 1. Project overview

Delvebound is an idle "expedition" RPG. Each run, every character (usually one human, Rey, plus 6 bots)
goes on a trip to a level-gated place, fights monsters turn by turn, may retreat or be defeated, gets
loot/XP/gold, and receives a mail report.

- **One Laravel 12 codebase** (PHP 8.2+) at the repo root, served by Apache at `http://delvebound.host`
  (web root `public/`).
- **Simulation:** the console command `php artisan delve:run`, started **manually** by Rey. There is no
  cron, no Laravel scheduler, and no queue worker.
- **Website:** Laravel controllers + Inertia.js 2 + React 19 + TypeScript + Tailwind CSS 4 (built by Vite).
  Sign-up/login, one account = one character. Pages change without full reloads.
- **Database:** MySQL 8.0 (`delvebound`).
- **Environment:** WSL2 Ubuntu 22.04. Apache runs PHP 8.2 (`mod_php`), the CLI has 8.3, so all code and
  every Composer dependency must work on **PHP 8.2** (Composer's platform is pinned to 8.2).
- **Status:** milestones M1–M4 and M6 (the Laravel move) are done; see DESIGN.md §13.

## 2. The architecture rule (non-negotiable)

**The website and the simulation share code, but they communicate state ONLY through MySQL.**

- A web request never runs, queues, schedules, or triggers a simulation. No `Artisan::call()`,
  `Process`, `exec`, `shell_exec`, queue jobs, or events that lead to `delve:run` from HTTP code.
- The simulation never calls the website (no HTTP, no sockets).
- The website writes *intentions* (stat spending, equipment, shop purchases, belt, `trip_orders`). The
  simulation reads them and writes *results* (`trips`, items, gold, XP, `mail`).
- **No "Run now" button** and no run-request queue. Runs stay manual (DESIGN.md §14, decision 4).
- **No external AI/LLM or network calls** anywhere in `app/Game` or `app/Simulation`. Bots are purely
  rule-based (DESIGN.md §8). `tests/Unit/NoNetworkTest.php` enforces this.

## 3. Folder layout

```

├── DESIGN.md README.md AGENTS.md .env.example   (.env is never committed)

├── app/Console/Commands/  # delve:run, delve:balance-lab, delve:check-content, delve:create-account, delve:make-admin
├── app/Http/            # thin controllers + middleware (run.guard, admin, Inertia shared props)
├── app/Services/        # web-side transactions (AccountService, CharacterService, ShopService, AdminContentService, GameQueries)
├── app/Models/Account.php   # the ONLY Eloquent model (Laravel auth)
├── config/balance.json  # every tunable number
├── config/delvebound.php    # game settings read from .env
├── database/schema/001_schema.sql, database/migrations/, database/seeders/ (+ sql/), database/sql/
├── resources/js/        # React: pages/, components/, layouts/, lib/, types/
├── resources/css/app.css    # Tailwind theme
├── routes/web.php
├── tests/fixtures/      # JSON cases (derived stats, place access, shop prices, XP)
├── tests/Unit/ tests/Feature/

```

Never put secrets in `public/` or commit `.env`. `public/build` is generated by `npm run build`.

Do not serve public assets from `/icons/`. Ubuntu's Apache config aliases `/icons/` to
`/usr/share/apache2/icons/`, so a file in `public/icons/` returns Apache's own 404. Item drawings live
in `public/item-art/` and are requested as `/item-art/…`.

## 4. Conventions

1. **One balance file.** Every tunable number (formulas' constants, XP curve, rarity weights, belt
   size, price formula, caps) lives in `config/balance.json`, read through `App\Game\Balance`. No magic
   numbers in PHP or TypeScript. Content values (monster stats, item stats, prices of individual
   listings) live in the seed SQL.
2. **One implementation, fixture-tested.** Formulas and rules live once in `app/Game` and are used by the
   website, the bots, and the simulation alike (derived stats, `canEnter` level gates, equip legality,
   shop price/sell rules, XP to next level). They must pass the JSON fixtures in `tests/fixtures/`. When
   you change a formula: update DESIGN.md, `balance.json`, the code, and the fixtures in the same change.
   The React UI **displays** values computed on the server; never re-implement a formula in TypeScript.
3. **Seeds for reproducibility.** Never use `rand()`, `mt_rand()`, `random_int()`, `shuffle()`,
   `array_rand()`, or `Str::random()` in `app/Game` or `app/Simulation`. Use `Rng::trip($seed, $charId)` /
   `Rng::bot($seed, $charId)`. The same seed + DB state must give identical results; tests rely on
   `delve:run --dry-run --seed=N`.
4. **Pure core.** Everything in `app/Game` takes arrays + an `Rng` and returns arrays. No `DB`, no
   facades, no `config()`/`env()` calls, no Eloquent. Only `app/Simulation/SimRepo.php` + `Runner.php` +
   `RunLock.php` touch the DB for the simulation, and only `app/Services/*` touch it for the website.
5. **One transaction per character.** A character's whole trip result (trip, encounters, items,
   consumables, XP/gold, order consumption, mail) is committed atomically after `SELECT … FOR UPDATE`.
   Bot decisions are one transaction per bot. Web writes are one transaction each, with a `row_version`
   check.
6. **Double-apply safety** comes from the DB: `GET_LOCK('delvebound_simulation')`,
   `uq_runs_one_running`, `uq_trips_run_char`, `uq_mail_trip`, `uq_botdec_run_char`. Don't remove or
   weaken these.
7. **Level gates are enforced in three places:** the website orders flow, the bot candidate filter, and
   the simulation snapshot (`order_rejected`). Always use `App\Game\Rules::canEnter()`; never
   re-implement the check inline (and never in React; the map shows the server's verdict).
8. **Security:** Laravel's CSRF middleware stays on for every non-GET route (Inertia sends the token).
   Query builder / bindings only; never interpolate input into SQL. React escapes output; never use
   `dangerouslySetInnerHTML`. Scope every game query by `Auth::id()` through `characters.account_id`, and
   never trust a posted character id. Validate every request (`$request->validate`). Every
   state-changing route has the `auth` and `run.guard` middleware; admin pages add `admin`.
9. **Database connections:** web code uses the default `mysql` connection (`delve_web`, limited grants),
   the simulation uses `sim` (`delve_sim`), and migrations/seeds use `--database=admin`
   (`delve_admin`). Admin content tools (`AdminContentService`) also use connection `admin`. If a
   player-facing website path needs a new write, extend `database/sql/grants_web.sql` too.
10. **Schema changes** go in a new Laravel migration in `database/migrations/` (raw SQL via
    `DB::statement` is fine and matches the SQL-first schema). Never edit an applied migration or
    `database/schema/001_schema.sql`. Update DESIGN.md §2 in the same change.
11. **Times** are stored in UTC (`app.timezone` stays `UTC`) and displayed in `DISPLAY_TIMEZONE`
    (Asia/Bangkok). Format dates on the server or with the shared helper in `resources/js/lib`.
12. **Frontend:** pages in `resources/js/pages`, shared pieces in `components/`, one layout in
    `layouts/`. Use Inertia's `<Link>`, `useForm`, and `router` so nothing reloads the page. Keep the
    existing theme tokens in `resources/css/app.css`.
13. **Scope:** don't add packages, frameworks, services, or new Eloquent models without a note in
    DESIGN.md's decisions log. Composer packages must support PHP 8.2.

## 5. How to run and test

```bash
cd /var/www/vhosts/delvebound

# Tests and checks
php artisan test                                  # unit + fixtures + feature + simulation tests
php artisan delve:check-content                   # must report no problems
npx tsc --noEmit                                  # TypeScript check
npm run build                                     # compile the UI into public/build

# Simulation (manual)
php artisan delve:run --dry-run --seed=42         # preview, writes nothing
php artisan delve:run                             # real run
php artisan delve:balance-lab --place=greenwood --level=1 --trips=1000

# Database
php artisan migrate --database=admin              # apply new migrations
php artisan migrate:fresh --drop-views --seed --database=admin   # dev reset: drops everything
```

Tests use the `delvebound_test` database (see `phpunit.xml`), never the real one.

To click through the site against the test database, use PHP's built-in server. **Don't use
`php artisan serve`**: it re-reads `.env` over your environment variables, so it would hit the real DB.

```bash
cd public && DB_DATABASE=delvebound_test APP_URL=http://127.0.0.1:8099 SESSION_COOKIE=delve_test_session \
  php8.2 -S 127.0.0.1:8099 ../vendor/laravel/framework/src/Illuminate/Foundation/resources/server.php
```

Before finishing any change: `php artisan test` green, `npx tsc --noEmit` clean, `npm run build` done
if the UI changed, `delve:check-content` clean, and a `delve:run --dry-run --seed=42` that still runs.

## 6. Where to add new content

All content is **data** (seed SQL + `balance.json`), not code. Add a new migration that inserts it (or a
new seeder SQL file for fresh installs, plus a migration for existing databases), then run
`delve:check-content` and the balance lab.

| Content | Tables / files | Checklist |
|---|---|---|
| **Place** | `places`, `place_monsters`, (optional) a `loot_tables` chest table | Set **`min_level`** (hard gate), **`rec_min_level`–`rec_max_level`** (recommended range), `rec_level` (bot target, inside the range), and **`max_level`** only for starter areas that high-level characters shouldn't farm (else `NULL`). These must satisfy `chk_places_levels` (`min_level ≤ rec_min ≤ rec_level ≤ rec_max ≤ max_level`). Choose monsters whose levels fit the range, set `encounter_min/max`, boss + `boss_chance`, `rarity_bonus`, `gold_mult`, map coordinates (`map_x`/`map_y` are % positions on that region's map). Add cases to `tests/fixtures/place_access_cases.json` if the gate pattern is new. Update the DESIGN.md §7.1 table. A new **map** (a `regions` row plus its places) follows [MAPS.md](MAPS.md). |
| **Monster** | `monsters`, then link it via `place_monsters` | Use the authoring formula in DESIGN.md §7 as a starting point; set `loot_table_id`, `drop_chance` (bosses 1.0, `is_boss = 1`), `damage_type`. Its level should sit inside the recommended range of every place it appears in. |
| **Item template** | `item_templates`, add it to `loot_table_entries` | Pick `slot`, `item_type`, `scaling_stat` (weapons), `two_handed`, base stats, `implicit_mods` (use the stat-key vocabulary from DESIGN.md §2.1), `req_level`, `base_value`. Put it in loot tables whose places match its level. |
| **Affix** | `affixes` | Unique `stat_key` vocabulary, `slot_groups`, `min_ilvl`, value range + `value_per_ilvl`. |
| **Bot personality** | `bot_profiles`, then a bot character (`is_bot = 1`, `account_id = NULL`, `bot_profile_id` set) with a starter kit | Stat weights, `preferred_scaling`, `gear_weights` JSON (keys hp, attack, defense, mres, crit, dodge, speed, mf), risk/retreat/randomness, memory params, shop params (`gold_reserve_pct`, `potion_target`, `buff_preference`, `shop_min_gain_pct`). Keep 6 bots unless DESIGN.md says otherwise. Bots must never bypass level gates or the shop rules. |
| **Shop item (gear)** | `shop_listings` (`kind='gear'`, `item_template_id`) | Common starter/low-level templates only; `price` from the formula in DESIGN.md §7.7 (`ShopMath::gearPrice`); `min_level` = template `req_level`. |
| **Shop item (consumable)** | `consumable_templates` + `shop_listings` (`kind='consumable'`) | Use an existing `effect_type`/`use_trigger` if possible. A **new effect type** needs code in `app/Game/Combat.php`/`Trip.php`, display in the React pages, a DESIGN.md update, and tests. Set `base_price`, `sell_price` (~25%), `req_level`. |
| **Balance tweak** | `config/balance.json` | Change the number, re-run the fixtures (update expected values deliberately), run the balance lab, and note significant changes in DESIGN.md. |
| **New page** | `routes/web.php`, a controller, `resources/js/pages/*.tsx`, nav in `layouts/GameLayout.tsx` | Reads through `GameQueries`, writes through a service in one transaction, routes behind `auth` (+ `run.guard` for writes), a feature test for logged-out access and tampering. |
